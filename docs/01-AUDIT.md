## 1. Shape of the repo

Static GitHub Pages site. No framework, no server, no router library — hashes and
iframes do the work.

```
IITM-Pages/
├── index.html                 # 1,053 lines / 57 KB — the whole app shell + inlined sidebar JSON
├── content/                   # 509 files — archived course pages (.u.zip.html, SingleFileZ)
│   ├── maths-2/
│   └── Term-Feb-to-May/{Mathematics-II,Statistics-II}/…
│       ├── Course Introduction/   Answer Key…/   Mock tests…/
│       └── Week 0 … Week 12/
├── markdown/                  # second app: the "Vault" reader
│   ├── index.html             # 158 KB SPA (tailwind CDN + marked + KaTeX + prism + lucide CDN)
│   ├── index.json             # 2.31 MB — navigation + full search corpus
│   └── extracted/assets/      # generated by `npm run vault` (not present in this checkout)
├── scripts/
│   ├── generate-sidebar.js    # scans content/, injects JSON between DATA-START / DATA-END
│   ├── extract-to-markdown.js # .u.zip.html → .md + extracted/assets/
│   ├── vault-builder.js       # builds markdown/index.json and injects it into markdown/index.html
│   └── *-pdf.js               # four generations of PDF export (html→pdf, premium, v3, v4)
├── src/input.css              # 139 lines — Tailwind source (compiled → assets/main.css)
├── assets/, libs/, handouts/, output/, versions/, lighthouse-results/
└── package.json               # scripts: vault, markdown:all, pdf, premium-pdf, v3-pdf, v4-pdf
```

Pipeline, as it actually runs:

```
content/**/*.u.zip.html
        │  scripts/extract-to-markdown.js  (jsdom + turndown, images → extracted/assets/)
        ▼
markdown/extracted/**/*.md  +  extracted-index.tmp.json (101 KB, temp)
        │  scripts/vault-builder.js  (cleanup, image rewrite, index + search corpus)
        ▼
markdown/index.json (2.31 MB)  ──injected──▶  markdown/index.html  → the Vault app
content/**/index.html
        │  scripts/generate-sidebar.js
        ▼
index.html  (<!-- DATA-START --> … <!-- DATA-END -->)  → the Archive app
```

## 2. The three front-ends

| Surface | What it is | Design language |
|---|---|---|
| **Archive shell** (`index.html`) | Dark `#1c1d1f` sidebar + white iframe. Dashboard is an overlay with 4-ish cards. Hash routing: `#<url-encoded file path>` → `iframe.src`. | Slate/indigo, Tailwind utilities inline, `#f8f9fb` canvas, Lucide via unpkg |
| **Vault** (`markdown/index.html`) | Separate full SPA: own sidebar, own search, own breadcrumbs, KaTeX, Prism, pagination. | *Different* dark theme, glassmorphism, its own CSS in 290 inline lines |
| **Annotator** (`scripts/annotator.js`, `libs/rough.js`) | Floating pencil FAB + toolbar, 8 tools, 3 weights, 5 colours, undo, "adaptive" mode. Loaded by both apps. | Indigo pill, its own duplicated styles (inline in `index.html` **and** in `src/input.css`) |

So the same product ships two unrelated skins, two navigations, and two copies of
the toolbar CSS that have already drifted (inline version uses
`backdrop-filter: blur(25px)` and `#4f46e5`; the `input.css` version uses
`bg-white/80` + `ring-black/5`).

## 3. What works well (keep it)

- **Coverage.** 509 archived pages across 2 terms/3 courses; `Week 0`–`Week 12`
  plus exam keys, mock tests, malpractice rules, supplementary content.
- **Deep links.** `index.html#content/Term-Feb-to-May/…/index.html` opens the exact
  page, expands the sidebar, marks it active, and works after a hard refresh
  (`findRootIndexForPath` + `loadSidebarMode`).
- **Extraction pipeline exists and is good.** jsdom + turndown, YAML frontmatter,
  images centralised into `extracted/assets/`, level/points/answer-feedback
  semantic injections in the renderer (`.points-badge`, `.ans-correct`…).
- **Annotator** is genuinely useful on top of archived pages and is reusable JS.
- **Zero build for the viewer** — plain HTML/CSS/JS, deployable by copying files.

## 4. Problems worth fixing (ranked by user pain)

### P1 — Reading a page means looking at an archived IITM page
The `iframe` loads a SingleFileZ capture: it brings the original site's header,
nav, footer, tiny type and its own scroll containers. The reader is the *content*,
but what you see is a scrappy snapshot. There is no reader typography, no
breadcrumb, no prev/next, no width control. This is the single biggest "unclean"
feeling in the product — and the markdown pipeline already produces a clean
version of the same page.

### P2 — No way to take content out
`grep -c "clipboard\|copy"` over both apps returns **0**. You cannot copy a page as
Markdown, cannot copy a week or a syllabus, cannot download a self-contained MDX.
For "paste into an AI model or personal notes" — the exact use case asked for —
the archive is currently a dead end.

### P3 — No syllabus / outline anywhere
The only overview is a 4-card dashboard where each card prints
`${node.children.length} Modules / Weeks` — which is why `maths-2` and
`Term-Feb-to-May` both claim "2 Modules / Weeks": it counts *top-level children*,
not weeks, not pages. There is no screen that answers "what is in this course,
week by week, and how much of each kind".

### P4 — Three indexes that disagree
- `index.html` inline `#site-data` — folders/files only, paths ending
  `…(4_4_2026 8_44_18 am).u.zip.html`.
- `markdown/index.json` (2.31 MB) — navigation + separate `search` corpus +
  `breadcrumbs`, names with the scrape timestamp mangled into them
  (`AQ1.1  Activity Questions 1 - Not Graded   IITM Online Degree (3 4 2026 …)`).
- `extracted-index.tmp.json` (101 KB) — a build intermediate that is committed.

No `term`/`course`/`week`/`type` fields anywhere. Every feature that needs
metadata (syllabus, filters, grouping, counts, sharing) currently has to
*re-parse* a path string.

### P5 — Inconsistent, partly duplicated styling
- No token layer: colours are literals (`#1c1d1f`, `#242528`, `#4d3cc9`,
  `indigo-500`, `#4f46e5`), radii and spacing are utility strings.
- Sidebar labels clip badly: `L1.3_ Systems of Lin…`, `Practice assignmen…`.
- Icon sets: Lucide (unpkg) in `index.html`, Lucide again in the Vault, plus four
  hand-written inline SVGs in `getIconForFile`. Three "file" icons for the same
  concept.
- Dashboard mixes a filled indigo gradient card, a dashed indigo card, and plain
  white cards with no rule about what gets which treatment.

### P6 — Offline-first claim vs. five CDNs
Both apps pull from `unpkg.com`, `cdn.jsdelivr.net`, `cdnjs.cloudflare.com`
(lucide, tailwind play CDN, marked, KaTeX, Prism, rough.js). On a plane, in a
hostel with bad Wi-Fi, or on GitHub Pages' cold cache, the "offline archive"
fails to render. The Vault is worse: it uses `cdn.tailwindcss.com` (play CDN,
explicitly not for production) and re-downloads KaTeX fonts per visit.

### P7 — Payload and startup
`markdown/index.json` is 2.31 MB and is *inlined into the HTML as well*, so the
Vault page is ~2.5 MB before a single document loads, and its search corpus is
re-parsed on every visit. `index.html` is 57 KB because the sidebar tree is
inlined — fine, but it is regenerated by a script that mutates the app file in
place (`generate-sidebar.js` rewrites `index.html`).

### P8 — Mobile, a11y, and detail bugs
- `renderTree` emits `role="button" tabindex="0"` **twice** on the same div
  (`index.html`, folder header) — duplicate attributes, invalid HTML.
- Folder headers are `div[role=button]` with `onclick` only; no `keydown` handler,
  so keyboard users cannot expand folders.
- `.folder-content` uses `hidden` toggling with no `aria-expanded`.
- Arrows/breadcrumbs absent on mobile; the mobile header is a bare title bar.
- `package.json` has `"test": "echo … && exit 1"` — no tests, so refactors are
  unverified; `lighthouse-results/` exists but nothing runs it.

### P9 — Name hygiene
Archived names carry the scrape timestamp and the source-site suffix
(`_ IITM Online Degree (4_4_2026 8_44_18 am)`), `&`/`_` mashups, and mixed
`L1.1_` / `L2.1 ` separators. The sidebar shows raw-ish names; the Vault shows
space-collapsed names. `vault-config.json` already has `prettyNames` /
`excludePatterns` — the rules exist but are not applied to the main sidebar.

## 5. What "better" means, concretely

1. **One shell, four screens** — Home, Syllabus, Reader, (optional) Vault-as-Reader,
   with a command palette instead of two sidebars. → `02-IA-AND-DESIGN.md`
2. **Syllabus as a first-class screen** — every term → course → week → item on one
   page, with counts and a Copy-as-Markdown action. → `03-SYLLABUS-AND-MARKDOWN.md`
3. **Copy MDX everywhere** — per page, per week, per course; text-only, with
   inline images, and as a downloadable bundle. → same doc
4. **Clean design** — one token set, one accent, one type scale, one icon rule,
   reader typography for archived pages. → `02-IA-AND-DESIGN.md` §4
5. **One manifest, generated** — `data/manifest.json` with real metadata; every
   screen and both pipelines read it instead of re-parsing paths. → `04-ROADMAP.md`
